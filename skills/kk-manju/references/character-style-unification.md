# 多角色画风统一（可选增强）

用于人物身份、服装或多视图已经存在，但并排观看时像来自不同作品的情况。用户说“统一画风”“用 Nano 洗多视图”“用 STYLE LOCK 重绘”时调用；AI在资产盘点或跨镜审查发现媒介、塑形和材质差异时可主动建议。此功能是已有资产的定向重绘，不是每个项目的必经步骤。

## 1. 建议、选择与目标

- 先指出具体差异，例如真人肖像与三维数字角色混用、皮肤高光和发丝细节尺度不一致；不要只说“不够高级”。说明建议调整哪些资产、会增加哪些生成任务，并沿用已有授权。
- 用户明确要求执行该功能且目标已知时直接推进，不另问“是否启用”。只是在讨论、接受建议或要求存入 Skill 时，继续分析和准备，不据此额外生成。用户选择跳过后继续原流程，除非出现新问题，不反复推荐。
- 复用已经选定的项目风格母参。确实缺少方向、需要使用者决定以哪张图为基准时，先展示或准确定位真实候选，提出推荐，等待这个关键选择；继续做原图盘点、差异分析和提示词草案，不把等待时间当作选择完成，不先提交依赖该选择的收费生成。
- 支持只处理偏离的角色、保持合适角色原图，或按用户指定范围处理全部；风格母参本身不因其作为参考就必须再重绘。角色数、画幅、视图数、分辨率和每人张数均按项目选择。
- 新探索风格按既有 MJ 路线；已有风格母参下落实角色统一可用用户选定的 Nano 等资产编辑模型，不为此强制重跑 MJ。保持项目平台，查询实时模型契约与真实别名，不把平台名称当作底层厂商证明，也不虚构参考权重、seed、去噪强度或专用风格参数。

## 2. 先分离“保留什么”与“重建什么”

核对当前实际采用的源图、精确节点/单张输出、版本和真实文件。较新的候选不自动取代已采用旧版，已退回版本不混入。

| 约束 | 应保留/控制 | 允许变化或不得继承 |
|---|---|---|
| 身份 | 可辨识的五官关系、年龄、性别、体型、发型、表情特征 | 可重建表面成像与光线；不强求原照片毛孔、高光、发丝和边缘像素不变 |
| 衣装与物件 | 轮廓、层次、纹样位置、配饰归属、固有色、鞋型 | 织纹尺度、粗糙度、高光和褶皱的渲染方式可随共同风格重建 |
| 共同风格母参 | 媒介、形体风格化程度、皮肤/头发/织物表现、光影与清晰度 | 不继承母参人物的五官、年龄、性别、发色、服装、姿势或道具 |
| 版式 | 当前指定视图、顺序、比例、裁切和用途 | 小视图是否无脸按项目；人物板版式不传入剧情镜头 |
| 色彩 | 各角色固有色和色彩关系 | 环境冷暖统一不等于衣装全部改色；色卡不独自定义媒介 |

同批使用同一份风格核心，角色身份段分别编写。原图只允许局部编辑且不允许改变渲染方式时，说明这一目标不同于强风格统一；不同时承诺“保持原图所有质感”和“明显换成另一套渲染风格”。

## 3. STYLE LOCK 的强约束写法

“强锁”是把目标与参考职责说清楚的提示词组织方式，不是模型的硬锁开关，不能保证一次完全执行。已有 STYLE LOCK 仍失败时，先读实际提交正文、连线和结果；不要假定只缺某个风格词，也不要通过反复堆“严格”“必须”代替诊断。

正文按以下骨架写，数量与服务参数另列：

1. **目标媒介与转换动作**：明确真人摄影、半写实三维游戏 CG、二维动画等实际选择；写清是重新表现整个人物的渲染质感，还是只改局部。用户以“比如”提出的风格词可作候选，不自动成为所有项目的固定风格。
2. **真实参考与分工**：用当前服务支持的精确节点引用；身份/衣装来源和风格来源实际接入，编号由服务转换。
3. **共同渲染标准**：以母图可见特征说明形体、皮肤、发束、衣料、光影、色彩与锐度。不是只列“电影感”“高级”“真实”。
4. **内容不变量与可重建项**：身份、年龄、衣装结构和固有色保持；若源图材质与母参冲突，重新表现其表面质感，同时仍维持人物辨识，不用改脸或年轻化换取同风格。
5. **版式和输出用途**：按当前任务保留相应视图，不把大片景深、噪点或电影画幅机械放入多视图资产板。
6. **少量针对性排除项**：排除本轮实际发生的媒介漂移、串脸、色偏。每份角色正文只留下适用的描述，不在无胡须角色中残留另一人的胡须条款。

下例仅适用于选择“半写实三维游戏 CG”的项目；实际母图的特征仍优先，不直接用于真人或二维项目：

> [STYLE LOCK — SEMI-REALISTIC 3D GAME CG]
> 将这位角色重新表现为与已选风格母参同一套渲染语言的半写实三维游戏 CG 数字角色。整张人物板使用明确而统一的三维塑形，人体有可信体积，形体和表面经过适度艺术化整理。皮肤呈现柔和连续的明暗与克制微肌理；头发以有厚度的发束和选择性的细丝构成；衣料先呈现重量、层次和褶皱，再保留适量织纹。高光、阴影、边缘锐度和细节密度跟随母参。保留角色年龄：老人的骨相与皱纹用同一套 CG 渲染表达，不能磨成年轻人。
>
> 身份参考决定这是谁、穿什么及当前版式；风格母参决定如何塑形、着色和表现材质。保留身份与衣装结构，允许重建源图的皮肤、须发和织物表面及光照。将原有摄影质感转成目标 CG 质感，不能只叠一层颜色或柔化滤镜。不得复制风格母参人物的脸、年龄、性别或服装。此任务不输出真人棚拍或二维平涂画面。

语义优先级不能替代平台参考强度参数。源图控制过强或整板负担过大只是待查假设；使用真实支持的设置，不能声称通过“排在第一个”或“写大写字母”获得确定权重。

## 4. 按授权并发执行与对照

- 本轮已指定多个角色且共用现成母参时，默认在平台容量内并发，保留用户要求的总人数和每人张数；不擅自收窄为先做一个角色。只有实际缺少后继所需的新参考、用户要求先验小样或已核实容量/预算限制才分阶段。共享既有风格母参不产生串行依赖。保留原图、请求、实际结果与本轮改变的变量。
- 整板承担身份、服装、多个视角和媒介转换仍不成功时，可建议先做单视角的身份与风格验证，成功后再派生多视图。改变交付形态或增加数量要符合当前授权，不因一次整板失败自动扩批。
- 风格母参需要裁出肖像/材质区域时，只做可追溯的参考准备，保留原件与裁切范围；实际上传并绑定后才称为引用，不能以“准备了裁图”冒充完成风格迁移。
- 不默认“先 Nano 洗一次，再套 STYLE LOCK 洗第二次”。在一次重绘中落实锁定与统一即可作为首轮。只有观察到明确剩余问题且当前范围允许，才设计后续局部修订，避免无依据累积重绘漂移。
- 依[制作流程](production-workflow.md)和[脚本约定](automation.md)领取、提交、回读与保存；候选建新版本，不覆盖原采用资产。用户要求“先发给我看”时优先展示已有结果，后续方向留在准备阶段。

## 5. 分开审查与采用

先按近似人物/脸部显示尺寸并排看全组，再分别对照每张原图。正常年龄差、衣料种类差和固有色差不是风格不统一。

- **同剧感**：三人是否共享同一媒介、塑形程度、材质细节尺度、光影与锐度，而不只是相同背景色。
- **身份与年龄**：五官关系、老人/青年/少女比例和表情辨识保住；没有借用风格母参演员。
- **衣装与颜色**：剪裁、纹样、配饰、鞋型和本色保住。用整体冷调造成靴子、发色等偏移要单列。
- **多视图结构**：视角、脚尖/鞋跟、同一体型、完整头脚以及脸部用途正确。
- **采用依据**：生成完成、文件解码、风格通过、身份通过、用户选择分别记录。允许部分角色通过、部分保留旧版；整组统一失败不等于每张图完全不可用。

用户明确委托“如果合格就采用”时，可在上述目标通过后按授权更新当前项目的采用映射，标明由助手按条件审查，不伪记成用户逐图选定。尚未达到目标时展示差异与候选，不自动替换正式母版；用户另行明确选定某张时保留原审查意见并记录其选择。不要批量改写历史生成任务或旧集成片；只给未提交的后续任务更新引用。

## 6. 无效时怎样修

| 观察到的结果 | 下一次值得验证的改变 |
|---|---|
| 身份保住但仍是原来的媒介 | 明确整板渲染转换，检查是否同时冻结旧材质；核对共同风格参考已真实接入 |
| 只变冷暖、背景和柔和度 | 将形体、皮肤、发束、织物的可见目标写完整；不能以调色接近判风格通过 |
| 风格接近却换脸、年轻化或衣装串色 | 收紧身份/年龄/固有色职责，检查多输出或混入的参考，不靠再加风格词修身份 |
| 强约束仍无稳定改善 | 停止同条件追加抽卡，保留候选，重新讨论参考拆分、单视角验证或模型路线 |

模型内部如何分配权重通常未验证；诊断区分观察事实、推测原因和下一次测试。母参、提示词与参数同时改变时，不能将改善单独归功于“加了游戏 CG”。一轮结果也不能证明 Nano 不支持该方法或所有角色必须洗图。
