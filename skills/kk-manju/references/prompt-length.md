# 提示词长度检查

提交前核对当前平台、模型和模式的限制，检查最终完整正文（包含换行、引用标记和追加参数）。不要把英文词数、中文字符、UTF-8字节、UTF-16单位或token混为一谈。没有正确tokenizer时不得用词数冒充token数。

`prompt_guard.py`报告上述可测长度、正文指纹、约束来源、是否超限；只检查、不截断、不提交。`pipeline.py`在audit/init/ready/claim前调用它，超限不领取任务，封存请求中保存检查报告。record/review/deliver继续恢复已受理任务，不能因新预算丢掉旧回执。

已核实的schema/UI/供应商限制写入任务`prompt_limits`，同时记录source；多条限制同时满足。模型契约没有maxLength不等于无限长，也不能拿其他供应商的数字冒充当前入口上限。当前MJ8.1/8.2先采用900字符内部工作预算，明确不是官方硬上限；后续核实真实上限后按实际约束与余量调整。其他模型没有默认套用MJ预算，执行器应按自己的平台限制或明确内部预算检查。

示例（数值仅演示，source须换成当前真实证据）：

```json
{"prompt_limits":{"max_chars":800,"max_utf8_bytes":2400,"source":"当前模型schema或输入框的核验记录"}}
```

```sh
python3 scripts/prompt_guard.py /项目/最终提示词.txt --model mj-v8.1
```

超限时保留原稿，精简重复说明并保住身份、关键事件、镜头和连续性；需要拆任务时按镜头设计重新规划，不机械截断。每次改写后重检。若平台会自动缩写，也不依赖它替代提交前检查。实际调用前若又加了引用/前后缀，执行器重新检查实际发出的字符串。

服务报错、审核拒绝、参数超限分别按真实回执判断。一次成功不证明没有自动缩写；一次内部错误也不能直接判定为超长。
