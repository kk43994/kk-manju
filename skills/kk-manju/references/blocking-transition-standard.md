# 文字站位图与转场动画规范

版本1，2026-11-07。服务于两套独立规范：导演先决定站位、表演、摄影与转场，提示词再忠实编译。用户后续修正优先，已受理任务不因规范升级重投。

## 1. 文字站位图

剧本使用【人物：角色规范名】、【场景：地点名】、【道具：物件名】、【位置：地标/区域】。人物标记指同一身份资产；造型和状态另列，不随换镜重新选演员。内部占位符不是实际平台挂图凭据。

每场固定俯视底图方向：上北下南、左西右东为图纸约定，不推断真实地理北向。标清固定地标、出入口、边界、障碍与可走通道；实质调度增加起点/终点状态图。只换景别且站位不变时引用同一状态，不复制整图。

```text
                  北／门内
               【人物：角色甲】↓
 ──【西门柱】────门槛────【东门柱】──
       【人物：角色乙】↗
                    【人物：角色丙】↖
                            【摄影机A】↖
                  南／平台
```

- 紧贴人物的箭头为身体主要朝向；站/坐/卧/跪及支撑另写。
- 视线单独写“角色甲→角色丙”，不与身体或移动混用。
- 人物路线写起点→经过地标/接触→停点，注明发生在哪一镜。
- 摄影机路线写A0→A1，单独说明触发、方向、速度、终点和工作侧。
- 图纸东西不等于成片画面左右；每个机位另写画面左右、互补视线、遮挡和焦点。
- 角色离席后标空椅，门窗/桌椅/道具不随角色消失。关键道具的持有者、手、状态与尺度随镜交接。

导演图保留符号；最终模型正文转换为可见关系，不让成片显示箭头、机位、占位字或图板。真实参考和取景仍须核对通路、遮挡、接触距离与轴线。

### 多人复杂站位的执行锚

**预计同框四人及以上的每个镜头都必须冻结人物站位锚定**；两三人镜若有交错走位、指定动作对象、出入画、遮挡或连续运镜造成的归属歧义，也要做。四人门槛不强制生图，先判断 TXT 是否足以把关系写清，必要时再做图片锚。把每个角色的**唯一身份、起终位置、身体朝向、视线对象、移动路线和持物**逐项写清，再写摄影机起终点、工作侧、取景边界和画面左右。另列全场人数、各动作阶段实际入画人数、画外听者及前后镜左右顺序。人物被遮挡或离画后，不能在画内生成替身或复制体。

执行锚有三种形式，按镜头复杂度选其一或组合：

1. **文字 TXT**：保存可复核的俯视站位图与状态表；提交视频时将关键关系编译进最终提示词正文，或在平台确实支持文件参考时实际附上。仅在本地保存 TXT，不等于视频模型已获得站位锚。编译时使用可见的屏幕左右、距离、目光和动作接触，不让模型绘制图纸符号或文字。
2. **代码绘制俯视占位图**：人数/左右前后/道具归属可以用简单几何形状说明时，优先从同一份站位数据渲染 PNG 或 SVG；每名角色只绘制一个有唯一 ID 的人体符号，标出机位工作侧、朝向、彼此距离、关键道具及持有的手。先人工看图数人、检查左右和遮挡，再上传并将返回的真实图片节点接入视频任务；本地截图或仅在正文提及图名不算锚定。图的职责是空间关系，不是成片画风、机位或可显示的 UI；视频正文要明确禁止继承文字、箭头、色块、白底和俯视角度。代码图不需要模型积分，也避免生图模型自己先把人数画错。
3. **模型生成站位图**：代码图不足以表达复杂高低层、接触、遮挡或真实透视时，可用项目已选图片模型制作单张俯视站位图或分阶段关键帧。制作前沿用已锁定的角色与场景资产，确认本次图片费用；画面必须能数清唯一人物及地标，任何多出的人像都应退回重做。视频任务须绑定真实返回的图片节点，并标明它只控制空间/动作阶段，不继承图上的标注、白底、版式或与本剧不同的画风。计划制作的图片、未返回的任务和本地路径均不能冒充已绑定参考。

同框人数曾经增殖的返修镜，在正文加入机器可复核的**唯一实例约束**，如 `CAST={A:{instances:1,slot:LEFT},B:{instances:1,slot:RIGHT}}`、`FOR_EVERY_FRAME: count(A)==1 && count(B)==1 && count(all_people)==2`；道具同样记录 `count(PROP)==1`、持有者和手。再把这套约束翻译为自然语言的可见关系，避免只贴伪代码。若成片镜头不是俯拍，明确“图为俯视排练图，实际摄影机仍在指定工作侧”；不让图覆盖已定的导演镜头。锚图能降低歧义，**不保证模型守约**，返回后仍要逐帧核人数、身份和道具。

提交前核对最终正文与实际参考顺序、人物数量、画面左右、机位工作侧、动作对象及前后镜末首状态。回片逐阶段数人并检查朝向、接触、遮挡和轴线；四人及以上镜头没有站位锚、发生人物增殖或身份错认时一律不得标为采用。保留原片，优先缩小该镜可见人物/动作范围或补准确站位图，再做新候选。

## 2. 转场动画设计到三段

信息接力、声源接力、动作与尺度接力、声场承接和实体遮挡的选用与正文示例见[衔接技巧库](shot-handoff-techniques.md)；声音的进入、延续与退出依[声音设计规范](sound-directing-standard.md)。普通镜内剪接与跨视频动画分别处理，选定的声音桥不替代本项目所需视觉动画。

每个跨视频切口共用一张转场卡：**前段起势/带出 → 交界画面与切点 → 后段接入/揭示**。声音桥同时设计，但不能替代所需视觉动画。

转场卡包含：

1. 前后视频、末镜/首镜、起终站位状态。
2. 动机：为何在此转，传达何种时间/空间/注意力变化。
3. 动画样式与载体：实体前景遮挡、有动机的同向摇移模糊、云雾/主观层切换、动态构图匹配等。
4. 前段具体起势与后段具体揭示；各自到哪一动作阶段，不重演。
5. 统一的画面运动方向、交界视觉锚点、切换条件。
6. 成片可见总时长及两侧分配，与生成余量分开。
7. 声音、持物/服装/情绪/已知信息继承，以及明确的时间/空间省略。
8. 执行归属：generated（视频模型）、post（后期）、hybrid（分别说明职责）。

“快速自然转场”“接上一段”“淡入淡出”不能单独成为完整方案。跨片每处都有设计；镜内普通切镜按剧情选择，不统一套滤镜。最后一段明确本集收束状态，下一集确定后再锁跨集接入。

## 3. 门柱遮挡到新空间：完整方法示例

总可见0.6秒，前段0.35秒、后段0.25秒；这是本例选择，不是通用固定时长。

```text
前段末：旧场景仍在运动，近景门柱从画右向画左扫入。
                         ← ███

交界：门柱暖暗近景遮满画面，纹理和动势仍存在。
                 █████████████
                 在此条件切换

后段首：同色、同动势的遮挡接入，继续向左扫出。
          ███ ←               新场景从右侧显露
```

两侧共用“暖暗近景全幅遮挡、持续向左运动”的交界条件；不在前段扫完后段再扫一次，也不黑屏停一秒。后段用地标和人物位置完成重新定位。此效果承认省略中间路程，不能伪装成两个相隔地点物理连成一扇门。

先保证地理、持物、动作和情绪成立，动画再组织观看；不靠遮挡掩盖关键交接缺失。需要实际尾态保真时复用已审阅锚帧/真实尾段，计划画面不等于已取得输入。

## 4. director_contract数据约定

新叙事视频启用：

```json
"requirements": {"blocking_maps": true, "transition_animation": true}
```

`blocking_states`保存状态ID到图的映射：每项有`diagram`文字图和`actors`。actors以cast角色ID为键，每人写`position`和`facing`；可补pose/gaze/持物等事实。图中的【人物：姓名】与声明角色必须一致，无人场景允许actors为空。

每镜添加`start_blocking`和`end_blocking`，指向实际状态图。animation.from_blocking须对应前视频末镜的end_blocking，to_blocking对应后视频首镜的start_blocking。

在原transition上增加animation：

```json
{
  "mode": "generated",
  "style": "foreground_occlusion",
  "duration_seconds": 0.6,
  "out_seconds": 0.35,
  "in_seconds": 0.25,
  "direction": "画面右向左",
  "carrier": "近景门柱与门框",
  "bridge_frame": "暖暗近景遮满全幅，仍向左运动",
  "cut_when": "遮满全幅瞬间",
  "from_blocking": "本段末镜状态ID",
  "to_blocking": "下段首镜状态ID",
  "out_instruction": "门柱由右向左扫入，覆盖全幅时切出。",
  "in_instruction": "从同色遮挡全幅接入，继续向左扫出，新空间从右侧显露。"
}
```

以上是字段说明，ID须填实际值。out_seconds+in_seconds等于duration_seconds，两侧分别落在前末镜与后首镜有效区间，不能超过该镜时长。动画占已有镜头窗口，不额外机械增加剧情时长；handles_seconds仍是可裁剪运动余量，沿用原长度算式。

mode为post时填`post_instruction`，模型只保留干净运动素材；hybrid同时有两侧生成指令与后期指令，职责不重叠。编译器不把编辑器技术指令塞给模型，也不运行剪辑器；后期效果须核对实际工具能力和素材。

统一direction/bridge_frame/cut_when写入两侧，减少手写矛盾；元数据相同不证明返回像素和动势相配，必须检查实际切口。

## 5. 固定编译入口

```sh
python scripts/production_contract.py compile 项目/plan.json --output 项目/compiled-r1
```

先调用pipeline.validate，再按同一数据导出每条最终提示词、`调度与转场.md`和manifest，输出目录须是新目录。编译不领取任务、不联网、不提交生成、不渲染转场。

生成模式动画的两侧分别写入TRANSITION_OUT/IN；后期模式给模型保留干净素材的说明，编辑计划留在调度与转场单。SHOT_DESIGN保留逐镜表演、摄影和声音。文字占位标签转成可读对象名，平台Node引用保留；实际挂图仍由原参考流程完成，不凭文字发明节点。

领取时封存最终正文、所用站位图和成对转场计划；完整正文重新计量。媒体回读后记录计划/观察偏差，再决定采用或返修，保留旧版本。
