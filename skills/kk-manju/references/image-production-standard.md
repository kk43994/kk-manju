# 图片制作与摄影质感规范

用于资产图片、状态图、剧情试帧和摄影质感返修。镜头设计与视频提示词继续执行各自规范；实拍观感仅适用于本项目选择实拍的情况，不覆盖动画、插画等画风。

新项目先取得用户对基础规范、分集与画风方向的确认，再按[关键决策节点](guided-production.md)用MJ制作人物、场景风格候选并引导选定。进入每集时按[单集拆解与参考资产](episode-asset-preparation.md)明确实际角色/场景/事件/台词及所需视角，引导确定人物多视图、场景多视图、道具、造型与色卡等核心参考，在采用或具体明确委托后解锁相关派生。首次候选制作也须已有对应生成授权；已定母版与已授权独立资产沿原范围推进，不逐张重问、不把正向反馈扩大为批量收费授权。

## 1. 用途与参考职责

先核对原剧本、既定镜头和已确认母版。区别身份板、衣装/状态变体、空间板、道具板与剧情画面；人物三视已定时不因试风格重新选演员。记录必须保留与允许重建的内容。

每张实际参考记录来源、版本/指纹或节点、输出序号、控制范围和不得控制的范围：

| 职责 | 控制 | 不自动控制 |
|---|---|---|
| 身份与衣装 | 五官、体型、已定衣装 | 母版姿势、光线、分格版面 |
| 空间 | 门窗、通道、地标与朝向 | 每个机位复制同一背景构图 |
| 道具与状态 | 形制、归属、持手、干湿/损坏 | 无关人物与场景 |
| 构图与调度 | 视点、主体占比、接触及动作阶段 | 来源图错误材质和假纹理 |
| 色卡 | 约定色系及用途 | 整图涂同一色 |
| 摄影与风格 | 光影取舍、细节尺度、皮肤发束与整幅成像 | 参考演员、服装、地点和无关剧情 |

文字列参考不等于实际绑定。提交前核对真实附件、节点、输出序号、引用标签与工具参数。选定多输出节点中的一张时只绑定那张；工具只能整节点引用时建立单幅参考，不把整组候选一起喂入。

已定人物转多视图属于派生：默认简短说明“参考原图人物生成四视图，保留原图画风、身份、衣装和材质”，再写实际版式、无脸规则、全脚入画与方向。没有风格改写需求时，不另加painterly、引擎或摄影流派等重新定义媒介；派生步骤不重新做角色设计。简短指令是否更有效仍由实际图比较，不把一次修订当作模型规律。

用户明确要统一或重绘现有角色画风时，改按[多角色画风统一](character-style-unification.md)：共同母参控制媒介与渲染，身份图控制人物和衣装；保留内容而允许重建表面质感。不要把上面的“保留原画风和材质”派生指令带入这类改风格任务。明确的媒介词（如半写实三维游戏 CG）须有可见的塑形/材质标准，不作为硬锁保证或所有项目的默认值。

用户给画布截图选图时，先回查项目原节点、输出序号和已下载原件，视觉确认是同一张，再引用独立的高清原件。原件已存在时不以含界面按钮的低清截图替代。多产物节点须拆成选定单张参考，不能因此把其他候选也喂入；找不到对应原件才沿用用户附件，并如实记录来源分辨率。

### 现有资产的锚点回收与定向修复

在同一项目补场景、人物或道具前，先查画布和本地归档：记录**原始图片节点及单张输出、原件文件指纹、用户采用状态、已知派生节点**。用户截图若展示“图片节点 → 视频节点”，图片原件是场景/身份来源；右侧视频可供观察运动和构图变化，不能倒置血缘、把派生视频当原始母图。下载原件后做视觉核对，再给下游指定职责。

已有锚点出现无关人物、错误字样等局部缺陷时，以该原件为输入作**指定区域/对象的定向修复**；提示词写清允许改变什么，以及必须保留的空间地标、物件布局、视点、光向、画幅与角色身份。原件与每轮修复图独立保存，记录尺寸和指纹；检查几何、道具和光向是否漂移。生成模型即使拿原件作参考，也可能重绘全图，因此“同源修复候选”不等于像素级复原或用户正式采用。若原图错误会污染视频，可将合格修复图作为待审工作参考，但必须在实际挂图与回执里标明其来源和状态；不得静默替换正式母版。

用户已明确同意为节省 LibTV 图片积分或修复画质，改用内置 ImageGen 等渠道时，仅对本次授权的图片任务切换；视频仍沿项目既定渠道。先回收已有原图，再做必要修改，不能把渠道切换误解为允许重设计资产。外部上传、画布节点、生成、审图和采用分别记录。

使用合适的用户参考或已采用作品，减少空泛风格词。助手选用的工作参考不能记为用户已采用；不擅自改写既有选择。场景、人物多视图负责一致性，不继承其分格、空白脸或工作室背景。

### 制作前主动准备三类设定板

进入人物/道具资产准备、剧情截帧或冻结关键帧时，主动盘点下列三类板，输出各自“已具备/缺失/待选/本段不适用”及真实来源。已有合适且已采用的版本直接复用；缺项先完成设定与提示词，在本轮已授权的生成范围内补制并回读结果。仅讨论或写提示词的请求不自动启动付费生成。不把三类板机械合并为一张，也不为无武器、无关键道具的段落虚构武器。

| 标准板 | 必须表达的内容 | 下游使用方式 |
|---|---|---|
| 色卡 | 主色、辅色、强调色，人物/衣装/环境的分配，光源冷暖与明暗主次；可读色块及对应说明 | 约束色彩关系与成像层级，不复制色块版式；黑白项目改写为主体、背景、衣装与亮点的灰阶分离，不照搬“低饱和”等彩色要求 |
| 武器设定板；无武器时按剧情准备关键道具板 | 轮廓、相对尺度、材质、结构、握持/接触区域；需要辨认的角度、工作状态与损坏变体 | 锁定具体形制和状态，动作镜头还须独立写清持手、朝向、接触点和受力；武器图不代替握持与身体设计 |
| 人物服装与造型板 | 同一角色的脸、年龄、体型、发型、服装层次、配饰和材质；按镜头需要提供全身、细节与其他视角，明确造型版本 | 锁身份与衣装，不继承展示姿势、工作室背景、多视图分格；换装、湿身、受损等单列状态，不把状态变化误当换人 |

制作色卡时读[色卡制作规范](color-palette-standard.md)，按用途选择规范1“分组制作板”或规范2“横向色带总览”，主动编译可复制提示词与颜色/用途清单，核对色值、文字和计数；13色与沙漠色系不是全局默认。

三类板服务于已选画风。画风未定时先走 MJ 风格探索；Image 在已定画风下落实设定板与剧情画面。色卡不能单独代表完整画风，服装板也不能独自承担全部摄影风格。

提示词编译前建立真实引用表：职责 → 资产版本/指纹 → 精确节点及单张输出 → 实际输入序号。截图中的排列仅是核查线索，须以本次真实提交列表和平台转换为准；不能永久规定“Image 1一定是人物”。若本次输入确为色卡、武器、人物，则分别绑定该实际顺序；LibTV沿精确节点占位符与真实连线处理，不手算服务端序号。审查时确认三类参考不仅有文字说明，而且实际挂入且职责没有颠倒。

### 黑白审片板与后续上色

用户选择黑白分镜时，先交可读的人物速写，检查镜序、机位、构图、动作、表情与衔接；身份和衣装轮廓仍继承当前采用的多视图。黑白板不承担最终配色验收，也不自动成为视频必用输入。

审片板默认沿[黑白手绘张力故事板规范](hand-drawn-storyboard-standard.md)按戏剧强弱分格，不强制凑满九宫格。用户已选3×3九宫格总览时沿该选择，让同场相邻镜头及必要运镜阶段同页；格数不等于切镜数或生成任务数。先做好逐格设计再提交，规则见[动作故事板的可视化执行](shot-design-standard.md#421-动作故事板的可视化执行)。已有图仅需重新展示排版时复用原图，不为改排版额外发起付费重生；需要修正画面时另按实际返修范围处理。

需要上色时另建上色版本：实际绑定已审黑白板（控制构图、机位、动作阶段）、色卡（控制颜色分工与明暗层级）、人物多视图（控制身份、发色、衣装和材质），逐项记清职责。不要只把黑白图作为唯一参考任由模型猜色，也不要把此步骤变成重新选脸或重新导演。没有上色请求时不提前制作彩色精修；原黑白板与上色版本分别保存。

## 2. 剧照先有事件与观看立场

剧情试帧写清：谁正对谁做什么、动作阶段、对方即时反应、观众先看哪里，以及机位和光线为什么这样安排。目光、身体朝向、接触、重量与支撑共同成立；一张图只选一个可同时存在的瞬间。

剧情截帧按下列骨架组织，字段只在有用时展开：输出形态 → 实际参考与职责 → 本镜局势及观众必须看清的关系 → 一个冻结动作阶段 → 姿态、握持、接触、受力与环境反馈 → 人物表演 → 机位、景别和可见范围 → 光向、明暗/色彩层级、材质与虚实 → 少量针对性排除项。模型、画幅、分辨率、质量和数量单独写入执行参数，界面复制残留不进入正文。

每张剧情截帧先回答“为什么选这一瞬间”。防守、攻击、反应等节点必须是一个可同时存在的状态，不能把接触前、接触中与恢复后的动作塞进同一张图。涉及动作时写清动作姿态 → 接触位置 → 受力反应 → 衣物/地面等反馈；火花、烟尘等效果不能遮掉关键接触。按表达任务决定景别和画面边界，支撑脚、持手或证据道具必须可读时为它们留出画幅，次要人物用外围/纵深关系交代，不要求每个人的全身与表情都同样清楚。

对称、中心构图、黑白、实拍、胶片和镜头标签都是本镜选择，不从示例推广为全项目默认。摄影说明优先写实际光向、落差、主体与背景分离及焦点关系；设备/胶片名称只作辅助，不能证明真实光学或材质。验图先检查核心关系、身份、武器形制、接触与支撑，再判断摄影质感。

交谈、对峙、救援、等待或决定都能有戏，不必强加大动作。避免把演员排成展示正脸或漂亮侧脸。是否看摄影机、加前景或浅景深，由用途与导演方案决定；角色板和无人空间板不强塞剧情。

参考的成像方法可迁移，爱情戏的亲密动作和暖软氛围不能自动替代悬疑、复仇等既定情绪。

## 3. 摄影观感的验收

先在正常观看大小判断人物、光影和空间，再用相近主体显示大小的局部检查材质。区分景别、照明、干湿、压缩和后期；低细节截图不能单独证明原片没有肌理。

- **皮肤先读形体与肤色。** 肌理由距离、受光和焦点决定可见程度，不以满脸毛孔、浮雕细纹证明真实。减少过强的小尺度对比，不把眼神、五官和骨骼转折一起磨平。干燥、出汗、泼水分开，湿润可有局部反光，不一律消除或放大成整片油膜。
- **头发先读发量与发束。** 厚度、重叠、遮挡和明暗先成立，细丝在合适的受光与焦点位置选择性出现；避免每根同样锐亮，也避免塑料条带或整片磨糊。干发和湿发的束感、高光不同。
- **光线有所取舍。** 暗部可以自然合并，不能为展示所有纹理全面补亮。冷暖光按真实来源作用于物件，不能只套整图色调。
- **虚实围绕焦点和叙事。** 不是机械“最近最清楚”；前景也可虚。关键人物/道具要可读，远处配角虽柔仍须读出必要动作。按距离连续递变，避免清晰人物贴在统一糊掉的背景上。
- **整幅成像协调。** 皮肤、头发、织物与环境共享光向、曝光、色彩与光学边缘。墙面保留成片结构，不堆碎噪。颗粒、光晕、柔化服从项目选择，不将所有颗粒视作缺陷，也不靠加滤镜掩盖错误。
- **像素规格与质感分开。** 2K/4K不是艺术质量标准。按既定规格和交付需要选择，不默认最高档；单个项目选择2K不变成全局固定值。

## 4. 工具分工与依赖

本流程的职责固定：**MJ 做画风探索与风格图，Image 落实已定画风下的角色、场景、状态与派生资产。** 用户给图探索尚未选定的画风，沿 MJ 风格候选路线；已经选择风格母参、要让现有人物/多视图统一，属于资产重绘，可按用户选择的 Nano 等适配工具执行。两者以任务目的区分，不因出现“风格”二字强制重跑 MJ，也不以资产图冒充未完成的风格探索。现成参考可直接复用，不强制为每张资产重跑探索、重构等全部阶段：

1. 用户确认画风方向后，确定实际视觉参考及职责，用MJ做当前范围内的人物与场景风格候选，按需分格对比并逐格编号。给出推荐，等用户选定实际版本；已有已选母参直接复用。跨角色风格试验区分可迁移的光影、材质、色彩、成像和不可复制的原演员、服装、姿势；核对入口实际支持的参考控制，不把普通图像参考宣称为专用sref算法。
2. 用户选定风格及人物/场景方向后，用Image等项目已选资产工具落实人物多视图、场景多视图、关键道具、造型与状态，实际绑定已选参考并按本集用途核验。风格候选不自动替换人物母版；Image不重新承担画风探索。核心参考供用户确定后再进入正式分镜，分镜新增的必要机位或状态按原方案补制；剧照的光影与细节主次在源图阶段建立，不全留给末端处理。
3. 按需要做材质/成像重构。例如Image负责具体画面，2.1做成像统一；源图已合适可跳过。锁定身份、剧情与必要构图，允许替换错误材质，不同时要求风格重建和冻结全部原像素质感。
4. 比较原图、源图与处理图，报告改善、回退及未解决问题，保留各版本。

同镜图像返修默认保留视点、透视、裁切范围、主体占比和关键落点，不能借质感处理变焦或改景别；导演确需重构图时另建修订并检查连续性。

独立资产/不同试帧可并发，状态变体依赖母版，处理阶段依赖实际源图。按授权规模、服务能力与pipeline.py claim调度。先用少量有代表性的试帧暴露问题；单人照不适合独自检验双人事件与深度关系。试验有结论后再扩展。

## 5. 审查、返修与停止

先查身份、衣装、道具归属、身体支撑、动作与空间，再查摄影质感。剧情或几何错误回源头修，不用洗图掩盖。

**结构检查通过、摄影质量通过、用户采用分别记录。** 诊断试验可在已授权计划内继续处理尚不理想的源图，但必须写明目的、缺陷和适用范围，不标成生产采用或让失败候选解锁批量视频。现有脚本review只存一个决策时，在审查文件明确本次决策针对的用途；最终目标未达标记失败，仍保留生成成功回执。

| 观察问题 | 优先修复 |
|---|---|
| 不知人物在做什么、互动僵硬 | 事件、表演、接触、观看立场 |
| 身份、持手、门窗、干湿错 | 参考与具体画面，不靠调色修剧情 |
| 油膜、毛孔/发丝刻线、背景碎纹 | 大光影与细节对比，重建错误材质，避免一律加锐或磨糊 |
| 变软、改脸、偏色、加烟 | 对照源图定位回退，局部修复或换路线 |
| 实际参考已挂入，风格仍几乎不变 | 检查旧构图图是否强带错误质感，考虑只保留其调度描述/空间依据，或换更适合重建的工具 |

尽量同源图、同尺寸、同模型比较；每轮记录变了哪些变量，无seed时说明随机差异。参考、提示词和源图生成方式同时改变，不能单独归因一项。模型内部原因未验证时只记假设。

在授权数量/预算内执行。连续试验未改善时，停止沿同一假设追加词或抽卡，展示最近结果并重新定位责任层。失败沉淀的是诊断方法，不是成功配方。

多视图若在正确单张原件、简短转换指令下仍把立体材质改成平涂，不能以版式正确放行，也不能继续声称只是提示词太长。回读真实模式、参考列表与源图，分别记录宿主挂图、服务参数和画面效果。整板反复失败时，停止同任务抽样；后续可先做单视角保真测试，验证身份/衣装/媒介后才扩展其他角度。该路线是待验证方案，不自动增加出图数量或替代用户选择。

## 6. 执行与交付

沿用[长度检查](prompt-length.md)和[调度恢复脚本](automation.md)，不临时另写调度器绕过稳定请求键与任务恢复。模型参数、参考比例及附件上限以当前契约和真实回执为准；超宽板被拒时回查正确来源或另出兼容版，不擅自换图。

用scripts/image_compare.py生成保持比例的等宽对比与原文件指纹；它只排版观察素材，不修图、不判定采用。裁切比较需核对同一部位与相近显示大小，不能替代全图审查。

使用平台官方可用的无水印导出设置，提示词不能代替平台设置。下载先写临时文件，校验完整解码与规格后原子更名，再制预览，避免读取未完成文件。

按约定在聊天展示实际图片并同步画布，分别记证据。生成、保存、显示、画布持久化和采用各自报告。英文术语和设备名称只有落实为可见执行时才有用，不代替参考和导演判断。
